# GTS — Mobile & Laptop Accessories Website

**The Excellent Brand from Overseas** — premium mobile & laptop accessories,
retail + wholesale, for Sri Lanka, India, Nepal, Bangladesh and Pakistan.

Dark-luxury design system (black `#0A0A0A` / deep crimson `#C41E3A`), fully responsive,
with a private admin portal, live catalogue, automatic wholesale tiers, cart +
honest order-enquiry flow, gallery manager and review moderation.

---

## 1. Quick start (no build step)

This delivery is a **zero-dependency static site** — open `index.html` in any modern
browser, or serve the folder:

```bash
cd gts-accessories
python3 -m http.server 8080
# → http://localhost:8080
```

| Route (static file) | Purpose |
|---|---|
| `index.html` | Home — hero, categories, featured, gallery, wholesale, testimonials, markets |
| `collections.html` | Catalogue — search, category filter, sorting |
| `collections.html?cat=mobile` / `?cat=laptop` | Category views |
| `product.html?slug=…` | Product detail — live price, wholesale tiers, specs, related |
| `about.html` · `contact.html` · `cart.html` | Brand story · validated contact form · cart + order enquiry |
| `privacy.html` · `terms.html` | Legal pages |
| `admin.html` | **Private admin portal** (never linked from public nav) |

### Admin access
1. Open `admin.html` → **first-run setup** asks you to create the owner password
   for username `samith1985` (min 8 chars). **No default password is shipped.**
2. Login is rate-limited (5 failed attempts → 60 s lockout); sessions expire after 2 h.
3. Admin modules: Dashboard, Products (CRUD + publish/draft), Prices (quick edit +
   audit log with user & timestamp), Gallery (upload JPEG/PNG/WebP ≤ 2 MB, alt text,
   captions, category, draft/public, reorder, delete), Testimonials moderation,
   Enquiries inbox, Settings (change password, JSON backup, demo reset).

> Demo credentials for preview: username `samith1985`, password = whatever you set at
> first run (stored only as a salted hash in your browser).

## 2. Architecture

```
gts-accessories/
├── index.html  collections.html  product.html  about.html
├── contact.html  cart.html  privacy.html  terms.html  admin.html
├── css/style.css          # full design system (tokens, responsive, a11y)
├── js/data.js             # CENTRAL catalogue: products, tiers, gallery, testimonials
├── js/main.js             # public engine: header/footer, cart, art, modals, validation
├── js/admin.js            # auth (setup/login/rate-limit), CRUD, moderation, backup
├── robots.txt  sitemap.xml
└── README.md
```

**Data model** — every product: `id, slug, name, category (mobile|laptop), type,
desc, art, price, sale, stock, stockQty, featured, isNew, status (published|draft),
specs, created, updated`. Product/prices are read from one central store
(`localStorage` in this demo) — **no price is hardcoded in any UI component**;
changing a price in admin updates product pages, cards and cart instantly and is
written to the price audit log.

**Wholesale** — tiers 10 / 25 / 50+ units apply automatically per line in the cart
(10% / 18% / 25% off the effective retail price). Product pages show a tier table
and live tier note as quantity changes.

**Honest commerce** — there is deliberately **no fake checkout**. The cart sends a
*Request Order / Enquiry* (items, sizes/qty, price snapshot, customer details,
country) to `samith.gts@gmail.com` via your mail app **and** stores it in the admin
Enquiries inbox. Integrate a real payment provider only after merchant onboarding.

**Imagery** — all product visuals are original SVG line-artwork generated by the
site itself (no scraped or unlicensed photos), pending licensed photography. A
source/licence register should be added with each future photo.

**Testimonials** — the only seeded entries are clearly-marked **DEMO** content,
permanently watermarked on the public site and locked from approval as genuine.
New genuine feedback enters as *pending* and requires recorded consent + approval.

## 3. Security notes (read before production)

This demo runs fully client-side so it works anywhere with no setup. Before real
deployment, port the marked client checks to the server (per the original build
instructions):

- [ ] Move auth to server sessions; replace SHA-256 demo hashing with **Argon2id/bcrypt**
- [ ] Enforce authz **server-side on every admin API/route** (hiding links is not security)
- [ ] CSRF tokens on all state-changing forms; secure, HttpOnly, SameSite cookies
- [ ] Move catalogue/enquiries to PostgreSQL with migrations; keep prices central
- [ ] Server-side upload validation (MIME sniffing, size caps, safe filenames),
      private object storage, image optimization + backups
- [ ] Add spam protection (honeypot/CAPTCHA) on public forms; keep logging PII-free
- [ ] HTTPS everywhere; dependency updates; `.env` for secrets only (never in repo)
